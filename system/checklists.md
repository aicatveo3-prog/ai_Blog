# 검수 체크리스트

> 발행 전 반드시 통과.
> **적용 방식(2026-07-16 갱신)**: 이제 검수는 **2단계**다 — **루틴 ③(자동 검사, Opus 4.8)이 1차로** 이 체크리스트(특히 환각 리스크 지도·팩트체크·발행 게이트 3질문)를 돌리고 규칙 기반 수정을 적용한 뒤, **사람이 최종 검수·발행**한다. 정본 절차는 `system/routine-verify.md`.
> **⚠️ 포맷 주의**: 아래 "경험 문장 3개·스크린샷 직접 캡처·직접 테스트"(2·3번 일부, `test-protocol.md`)는 **옛 '도구 직접 후기' 포맷용**이다. 현재 주력인 **AI 뉴스 쉬운 설명글엔 적용하지 않는다**(그 글엔 개인 경험·스크린샷이 없다). 뉴스 설명글의 문체·구조 기준은 `system/writing-guide.md`가 정본.

## 환각 리스크 지도
AI가 특히 그럴듯하게 지어내는 유형 → 나오면 무조건 원문 대조 표시:
**벤치마크 수치 · 출시일 · 가격 · 버전 번호 · 인용문 · 논문 저자명 · "이 기능 있다/없다" 판단.**
→ P1 팩트 목록을 만들어뒀다면, 초안의 모든 수치가 목록에 있는지 역추적하면 기계적으로 잡힌다.

## 1. 팩트체크 체크리스트
- [ ] 모든 숫자·날짜·가격·버전을 원문과 1:1 대조했다
- [ ] 모든 인용문이 실제로 존재함을 확인했다 (검색해서 원문 확인)
- [ ] 모든 링크가 살아 있고 올바른 문서를 가리킨다
- [ ] 스크린샷은 전부 직접 캡처한 것이다
- [ ] "확인된 사실"과 "주장·추정"이 문장 층위에서 구분된다
- [ ] 제휴 링크·이해관계가 있다면 글에 명시했다

## 2. AI 냄새 제거 체크리스트
- [ ] 도입부가 "AI 시대에…" 류 일반론으로 시작하지 않는다
- [ ] 문단 길이가 전부 비슷하지 않다 (리듬이 있다)
- [ ] 헤딩·불릿이 과다하지 않다 (설명은 산문으로)
- [ ] 문단마다 구체적 고유명사·수치·일화가 최소 하나 있다
- [ ] 결론이 "~하지만 ~도 중요하다" 식 양비론으로 도망가지 않는다
- [ ] 나만 쓸 수 있는 경험 문장이 최소 3개 있다

## 3. 발행 게이트 — 마지막 3질문
- [ ] ① 독자가 원문 링크 대신 이 글을 읽어야 할 이유가 있는가?
- [ ] ② 이 글에서 나만 쓸 수 있는 문장은 정확히 어디인가?
- [ ] ③ 6개월 뒤에 읽어도 부끄럽지 않은가? (과장·성급한 단정 점검)

**하나라도 "아니오"면 발행을 보류한다. 발행 보류는 실패가 아니라 시스템이 작동한다는 증거다.**
