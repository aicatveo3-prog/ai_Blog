# 포지셔닝 (Positioning) v1

> 이 문서가 이후 모든 선별·글쓰기·프롬프트의 기준이 된다.
> **핵심 결정**: 주제는 넓게(핫한 AI 소식 전반) 다루되, **관점(렌즈)은 하나로 고정**한다.
> → 주제로 좁히는 대신 "다루는 방식"으로 차별화한다. 그래야 "다 다루는데도 잡탕이 아닌" 블로그가 된다.

---

## 1. 이 블로그는 누구를 위한 것인가 (독자)

한 명으로 좁히지 않고 **넓게 포괄**하되, 다음 성향을 공유하는 사람을 중심에 둔다:

**내 독자:**
```
AI에 관심 있는 누구나. 단, "이 소식이 나한테 뭘 의미하는지"를 알고 싶어 하고,
막연한 요약이 아니라 실제로 써먹을 수 있는 이야기를 원하는 사람.
(개발자든 비개발자든, 직장인이든 사이드프로젝트를 하든 상관없다)
```

**이 독자가 다른 블로그 두고 굳이 내 블로그에 오는 이유 한 줄:**
```
남들은 "무슨 일이 있었다"까지만 전하지만, 여기는 "그래서 당신에게 뭐가 바뀌는지 +
직접 써보니 진짜 어땠는지"까지 알려주기 때문.
```

---

## 2. 무엇을 다루는가 (범위)

**주제는 넓다 — 그때그때 가장 핫한 AI 소식 전반.** 새 모델, 새 도구, 새 기능, 업계 흐름 무엇이든.
단, 아래 **두 개의 렌즈 중 최소 하나**를 반드시 통과시킨다. (이게 이 블로그의 정체성)

- [x] **렌즈 ① "그래서 나한테?"** — 이 소식이 독자의 일·도구·선택을 실제로 어떻게 바꾸는가를 반드시 짚는다.
- [x] **렌즈 ② "직접 써봤다"** — 도구·기능이면 가능한 한 직접 돌려보고 실측·스크린샷으로 검증한다.

> 즉, 주제로 거르지 않고 **"이 관점으로 쓸 수 있는가"로 거른다.**
> 핫한 뉴스라도 위 두 렌즈로 할 말이 하나도 없으면 → 안 쓴다 (그건 큰 매체가 더 잘 한다).

---

## 3. 무엇을 안 다루는가 (범위 밖)

"주제"로는 거의 안 거르지만, **다음은 예외적으로 거른다** (상세는 `scoring-rubric.md` 킬 기준):

- [x] 위 두 렌즈로 **할 말이 전혀 안 나오는** 단순 속보 (= 그냥 받아쓰기가 될 뉴스)
- [x] 단순 펀딩·인수 금액 뉴스 (업무·도구에 영향 없을 시)
- [x] 출처 불명 루머
- [x] 내가 직접 안 써본 도구의 "사용기" 흉내

---

## 4. 한 문장 정체성

**내 블로그 한 문장:**
```
핫한 AI 소식을 전부 다루되, 항상 "그래서 나한테 뭐가 바뀌는지" + "직접 써보니 어떤지"까지 알려주는 블로그.
```
