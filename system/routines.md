## 한눈에 — 상태가 흐르는 길

```
   루틴 ① 06:00              루틴 ② 07:00 (글쓰기 원샷)           🚦 사람
   수집(Haiku)               Sonnet 5                          최종검토·발행
뉴스 ─▶ [인박스]──────▶ 규칙 지켜 한 번에 완성 ──────────────────▶ 내가 확인 ─▶ [발행]
      3탭 구축              (교차검증→집필 중 규칙 적용→          OK한 것만    빌드·배포
      verified              저장 직전 자가점검, 최대 2편)
        │                        │                                    │
      inbox.json            drafts/v1.md (1개)                    build-seo.mjs
      collect/*.md          stage:검수중
```

| 상태 | 저장 위치 | 만드는 주체 |
|---|---|---|
| 인박스 + 3탭(정리본·자세히·반응) | `inbox.json` · `collect/*.md` · `collect/reactions/*.md` | **루틴 ①** Haiku |
| **검수중** (완성 초안 v1 · 버전 1개) | `drafts/<slug>/v1.md` + `posts.json` 등재 | **루틴 ②** Sonnet 5 (원샷) |
| **발행** (정적 페이지·OG·sitemap·feed) | `p/<slug>/…` 등 | **🚦 나 (사람)** + `build-seo.mjs` |

> **큰 그림**: 사람이 손대는 곳은 **딱 하나 — 맨 뒤 발행 승인**. 무엇을 쓸지(선정)는 "그날 수집된 검증·자료완비 뉴스 최대 2편"이라는 규칙으로 자동화했다.

## 🟠 루틴 ② — 자동 글쓰기 (원샷)  *(Claude 스케줄 트리거, KST 07:00)*  → 정본 `system/routine-write-verify.md`

> 옛 ②글쓰기+③검사를 통합했다가, 다시 **원샷 1패스**로(2026-07-20, 비용 최소화). 초안·검사를 나누지 않고 규칙을 처음부터 지켜 **한 번에 완성**한다(생성 1회). 품질 방어선은 posts.json 잠금 + 사람 발행 게이트.

| 항목 | 내용 |
|---|---|
| **모델** | **Sonnet 5** |
| **대상 (자동 선별)** | `inbox.json`에서 **① `surfaced`=오늘 ② `verified:true` ③ 3탭 자료 완비 ④ `postId` 없음** 을 만족하는 항목. **하루 최대 2편**(3개+ 이면 임팩트 큰 2편, 나머지는 다음 날). |
| **하는 일 (원샷)** | 대상마다: 교차검증(`prompts/K`) → **규칙을 지키며 집필**(`writing-guide.md` 17규칙 + 과단정 스캔·정직성·정밀표기를 **쓰는 중에** 적용, 환각 위험 항목은 원자료에 있는 것만) → **저장 직전 자가 최종점검 1회** → `drafts/<slug>/v1.md` **1개** → `posts.json` **append**(`stage:"검수중"`) → `inbox.json`에 `postId` 연결. **교정본 v2·REVIEW.md 안 만듦.** |
| **끝점** | 완성 글 1편(버전 1개)이 `검수중`에 대기. "N편 검수 준비됨" 알림. |
| **비용 원칙** | 생성 1회. 웹 재검색은 **의심되는 핵심 수치·최상급에 한해 최소로만.** |
| **트레이드오프** | 독립 검사자가 없으니 **과단정·환각을 사람이 발행 전에 더 꼼꼼히 봐야 한다**(최종 방어선=사람 게이트). |
| **절대 규칙** | ❌ build-seo·발행 금지 ❌ 2편 초과 금지 ❌ `발행`으로 안 올림 ❌ 사실 조작 금지 ❌ posts.json 통째 교체 금지(반드시 append). ✅ **0단계 발행 브랜치 강제 이동 + `git config core.hooksPath githooks`** → 커밋·푸시(posts.json 잠금이 커밋 검사). |

## 🚦 사람 게이트 — 발행 (자동화 금지 구역)

- `검수중`의 **v2 + REVIEW.md**를 읽고 최종검토·피드백(필요시 v3).
- OK하면: `posts.json` `stage:"검수중" → "발행"` + `published`(오늘) + **🔒 `publish-approvals.json`에 승인 등록** → **`node build-seo.mjs`** → 커밋·푸시.
- **여기가 유일한 사람 게이트.** 승인 없이는 어떤 글도 라이브로 안 나간다 — 이제 **산문이 아니라 기계가 강제**한다: `stage:"발행"`이어도 `publish-approvals.json`에 없으면 build가 건너뛰고 대시보드도 발행으로 안 띄운다. **승인 등록은 사람이 "발행해" 지시할 때만**(루틴·자동 금지).
- **posts.json 자체도 잠금(강함)** — `githooks/pre-commit`(→`validate-posts.mjs`)이 커밋 때 검사한다: 명단이 줄거나(①) 발행글 상태·발행일이 되돌려지거나(②) 초안이 껍데기(③)면 **커밋 거부**. 루틴이 실수로 명단을 덮어써도 대시보드가 안 무너진다. 사람이 일부러 지우거나(발행 취소 등) 할 땐 우회 스위치(`ALLOW_POSTS_SHRINK=1`/`ALLOW_POSTS_CHANGE=1`)를 붙인다. 서버측 백스톱: `.github/workflows/posts-guard.yml`.

## 왜 이렇게 끊었나 (현재: 수집 · 글쓰기 2단계)

루틴을 끊는 기준은 "일이 많아서"가 아니라 **경계가 진짜 있는 곳**:
1. **모델 티어가 바뀜** — ① Haiku(싸게 대량 수집) → ② Sonnet 5(글쓰기) → 발행 코드(무료).
2. **사람이 껴야 함** — 맨 뒤 발행 승인(유일한 사람 게이트).
> (옛 ③검사 단계는 폐지: 2026-07-20 원샷 전환으로 글쓰기 안에 자가 점검으로 흡수. 독립 검사 대신 posts.json 잠금 + 사람 게이트가 방어.)

## 비용 원칙 (요약)

- **수집=Haiku, 글쓰기=Sonnet 5(원샷·생성 1회), 발행=코드(무료).** (옛 Opus 4.6 초안 + Opus 4.8 검사 2회 → Sonnet 5 1회로 대폭↓.)
- **하루 상한 2편**으로 사용량 캡. 대상 0편인 날은 루틴이 즉시 종료(비용 0).
- **웹 재검색 최소화** — 의심되는 핵심 수치·최상급만. **프롬프트 캐싱**: 매 글마다 붙는 `writing-guide.md` + 골드 스탠다드를 캐시(~90%↓).
