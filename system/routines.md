# ⚙️ 루틴 운영 가이드 — 3-루틴 자동화 시스템

> 이 블로그가 "글 한 편"을 만드는 전체 흐름을 **3개 루틴 + 1개 사람 게이트**로 정리한 **운영 정본**.
> 파이프라인 7단계(수집·선별·조사·관점·초안·검수·발행)를 *주기·모델·사람개입이 바뀌는 3곳*에서만 끊었다.
> 관련: `system/daily-collection.md`(루틴 ① 플레이북) · `system/writing-guide.md`(글쓰기 기준) · `prompts/`(단계별 프롬프트) · `build-seo.mjs`(발행 빌드).

## 한눈에 — 상태가 흐르는 길

```
        ┌──── 루틴 ① (매일 자동) ────┐   🚦게이트    ┌──── 루틴 ② (필요할 때) ────┐   ┌ 루틴 ③ ┐
뉴스 ─▶ [인박스]──▶[3탭 구축됨]────────▶ 내가 선정 ──▶[조사]▶[초안]▶[검수]──────▶ [발행]
        status=인박스  collect/*.md          posts.json      교차검증  I프롬프트  F프롬프트    빌드·배포
                       reactions/*.md        등재(선정)                                (내 승인 후)
```

| 상태 | 저장 위치 | 만드는 주체 |
|---|---|---|
| 인박스 + 3탭(정리본·자세히·반응) | `inbox.json` · `collect/*.md` · `collect/reactions/*.md` | **루틴 ①** |
| **선정**(앵글·렌즈 확정) | `posts.json`에 항목 추가 | **🚦 나 (사람)** |
| 조사·초안·검수 | `drafts/<slug>/v1.md` | **루틴 ②** |
| 발행(정적 페이지·OG·sitemap·feed) | `p/<slug>/…` 등 | **루틴 ③** (내 승인 후) |

## 🚦 사람 게이트 — 자동화 금지 구역

- 쌓인 후보 중 **무엇을 글로 쓸지 1개 고르기** + **앵글·렌즈 확정**.
- 실행: `posts.json`의 `posts`에 `stage:"선정"`(→ 발행 시 `"발행"`)으로 항목 추가. **이 등재가 루틴 ②의 GO 신호.**
- 여기가 블로그의 taste가 결정되는 곳이라 **일부러 자동화하지 않는다.**

## 왜 7단계를 3루틴으로 묶었나

루틴을 끊는 기준은 "일이 많아서"가 아니라 **경계가 진짜 있는 곳**:
1. **주기가 다름** — ①은 매일, ②③은 필요할 때.
2. **모델 티어가 바뀜** — ① Haiku(싸게 대량) ↔ ② Opus(비싸게 품질) ↔ ③ 코드(무료).
3. **사람이 껴야 함** — 🚦게이트(무엇을 쓸지)와 ③ 승인.
4. **실패 격리** — ③이 터져도 원고(②)는 안 날아감.

## 비용 원칙 (요약)

- **수집·정리 = Haiku, 글쓰기·검수 = Opus, 발행 = 코드(무료).**
- **프롬프트 캐싱**: 매 글마다 붙는 `writing-guide.md` + 골드 스탠다드를 캐시(~90%↓).
- **배치 API**: 비급한 ① 수집은 반값.
- **애매한 것만 승급**: ①의 점수/날짜검증에서 확신 없는 항목만 상위 모델로.
