## 한눈에 — 상태가 흐르는 길

```
   루틴 ① 06:00              루틴 ② 07:00 (글쓰기+검사)          🚦 사람
   수집(Haiku)               Sonnet 5                          최종검토·발행
뉴스 ─▶ [인박스]────▶ 초안 v1 ─(깨끗한 문맥 검사)─▶ 검증·수정 v2 ──▶ 내가 확인 ─▶ [발행]
      3탭 구축              작성중        과단정 스캔+팩트 재검     OK한 것만    빌드·배포
      verified             (최대 2편)     +리포트 → 검수중
        │                     │                  │                  │
      inbox.json          drafts/v1.md      drafts/v2.md         build-seo.mjs
      collect/*.md        stage:작성중       REVIEW.md·검수중
```

| 상태 | 저장 위치 | 만드는 주체 |
|---|---|---|
| 인박스 + 3탭(정리본·자세히·반응) | `inbox.json` · `collect/*.md` · `collect/reactions/*.md` | **루틴 ①** Haiku |
| **작성중** (초안 v1) | `drafts/<slug>/v1.md` + `posts.json` 등재 | **루틴 ②** Sonnet 5 (Part A) |
| **검수중** (검증본 v2 + 리포트) | `drafts/<slug>/v2.md` · `REVIEW.md` | **루틴 ②** Sonnet 5 (Part B · 깨끗한 문맥 검사) |
| **발행** (정적 페이지·OG·sitemap·feed) | `p/<slug>/…` 등 | **🚦 나 (사람)** + `build-seo.mjs` |

> **큰 그림**: 사람이 손대는 곳은 **딱 하나 — 맨 뒤 발행 승인**. 무엇을 쓸지(선정)는 "그날 수집된 검증·자료완비 뉴스 최대 2편"이라는 규칙으로 자동화했다.

|---|---|

## 🟠🔴 루틴 ② — 자동 글쓰기 + 검사 (통합)  *(Claude 스케줄 트리거, KST 07:00)*  → 정본 `system/routine-write-verify.md`

> 옛 ②글쓰기(07:00)+③검사(08:00)를 **한 루틴·한 모델(Sonnet 5)**로 통합(2026-07-20). 편향은 '깨끗한 문맥 검사 패스' + posts.json 잠금 + 사람 발행 게이트로 보완.

| 항목 | 내용 |
|---|---|
| **모델** | **Sonnet 5** (쓰기·검사 모두). 검사는 **깨끗한 문맥의 서브에이전트**(초안+원자료+규칙만 주고, 작성 의도는 안 넘김 = 처음 보는 눈). |
| **대상 (자동 선별)** | `inbox.json`에서 **① `surfaced`=오늘 ② `verified:true` ③ 3탭 자료 완비 ④ `postId` 없음** 을 만족하는 항목. **하루 최대 2편**(3개+ 이면 임팩트 큰 2편, 나머지는 다음 날). |
| **Part A 글쓰기** | 대상마다: 교차검증(`prompts/K`) → 초안(`prompts/I` + `writing-guide.md`) → `drafts/<slug>/v1.md` → `posts.json` **append**(`stage:"작성중"`) → `inbox.json`에 `postId` 연결. |
| **Part B 검사** | 글마다 새 서브에이전트로: **과단정 스캔(규칙 17)** + 정직성·리스크(9·15) + 정밀표기(16) + **웹 팩트 재검** → 규칙 기반 수정 `drafts/<slug>/v2.md` → `REVIEW.md` → `stage:"검수중"`. 방향은 거의 항상 **'낮추기'**, 단 '한쪽만'은 반대 소스 보강. **문체·목소리 보존**, 앵글·taste는 플래그만. |
| **끝점** | v2 + 리포트가 `검수중`에 대기. "N편 검수 준비됨" 알림. |
| **절대 규칙** | ❌ build-seo·발행 금지 ❌ 2편 초과 금지 ❌ `발행`으로 안 올림 ❌ 사실 조작 금지 ❌ posts.json 통째 교체 금지(반드시 append). ✅ **0단계 발행 브랜치 강제 이동 + `git config core.hooksPath githooks`** → 커밋·푸시(posts.json 잠금이 커밋 검사). |

## 🚦 사람 게이트 — 발행 (자동화 금지 구역)

- `검수중`의 **v2 + REVIEW.md**를 읽고 최종검토·피드백(필요시 v3).
- OK하면: `posts.json` `stage:"검수중" → "발행"` + `published`(오늘) + **🔒 `publish-approvals.json`에 승인 등록** → **`node build-seo.mjs`** → 커밋·푸시.
- **여기가 유일한 사람 게이트.** 승인 없이는 어떤 글도 라이브로 안 나간다 — 이제 **산문이 아니라 기계가 강제**한다: `stage:"발행"`이어도 `publish-approvals.json`에 없으면 build가 건너뛰고 대시보드도 발행으로 안 띄운다. **승인 등록은 사람이 "발행해" 지시할 때만**(루틴·자동 금지).
- **posts.json 자체도 잠금(강함)** — `githooks/pre-commit`(→`validate-posts.mjs`)이 커밋 때 검사한다: 명단이 줄거나(①) 발행글 상태·발행일이 되돌려지거나(②) 초안이 껍데기(③)면 **커밋 거부**. 루틴이 실수로 명단을 덮어써도 대시보드가 안 무너진다. 사람이 일부러 지우거나(발행 취소 등) 할 땐 우회 스위치(`ALLOW_POSTS_SHRINK=1`/`ALLOW_POSTS_CHANGE=1`)를 붙인다. 서버측 백스톱: `.github/workflows/posts-guard.yml`.

## 왜 이렇게 끊었나

루틴을 끊는 기준은 "일이 많아서"가 아니라 **경계가 진짜 있는 곳**:
1. **모델 티어가 바뀜** — ① Haiku(싸게 대량) → ② Opus 4.6(초안) → ③ Opus 4.8(강한 검사) → 발행 코드(무료).
2. **독립성이 필요함** — ②가 쓴 걸 ③이 **다른 세션·더 강한 모델**로 검사해야 자기 글 옹호를 피한다.
3. **사람이 껴야 함** — 맨 뒤 발행 승인.
4. **실패 격리** — ③이 터져도 초안(②)은 안 날아가고, 발행이 터져도 원고는 무사.

## 비용 원칙 (요약)

- **수집=Haiku, 글쓰기=Opus 4.6, 검사=Opus 4.8, 발행=코드(무료).**
- **하루 상한 2편**으로 Opus 사용을 캡. 대상 0편인 날은 루틴이 즉시 종료(비용 0).
- **프롬프트 캐싱**: 매 글마다 붙는 `writing-guide.md` + 골드 스탠다드를 캐시(~90%↓).
