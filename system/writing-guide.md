# ✍️ 글쓰기 가이드 — 'AI 쉽게 알려주는 집'

> 이 블로그의 **정본 글쓰기 기준**. 모든 발행 글은 이 문서를 통과해야 한다.
> 확립 근거: `microsoft-mai` 글을 v1→v5까지 다듬으며 정리한 규칙.
> **골드 스탠다드(실물 예시)**: `drafts/microsoft-mai/v1.md` — 애매하면 이 파일을 열어 문장 리듬·구조를 흉내 낸다.
> (옛 `style-guide.md`는 이 문서로 대체됨.)

---

## 한 줄 원칙

> **"어려운 AI 뉴스를, 학생도 이해하게, 쉽고 재밌게. 단, 정확성은 절대 안 굽힌다."**

쉬운데(중학생도 이해) 안 유치하고, 재밌는데(계속 읽게 됨) 안 가볍다.
팩트는 정확하고, 판단은 독자에게 맡긴다.

## 독자 & 브랜드

- **독자**: AI에 관심은 있지만 전문가는 아닌 사람 — 학생·비전공자 눈높이.
- **브랜드 약속**: 복잡한 최신 AI 소식을 "쉽게 알려주는 집". 어려운 용어는 빼거나 풀고, 핵심만.
- **톤 한마디**: 똑똑한 친구가 옆에서 커피 마시며 설명해주는 느낌.

---

## 1. 문체 — 해요체

- **모든 문장은 해요체.** ('~합니다'체 딱딱함도, 반말도 아닌 중간. 친근하지만 예의.)
  - ✅ "공개했어요 / 써요 / 걸렸어요"
- 독자에게 말 걸듯. 관료체 금지("~에 관하여", "~라는 측면에서").
- 긍정형 우선. 안 되는 것도 되는 방향으로 돌려서.

## 2. 도입 — 장면으로 연다 (사실 나열 금지)

- ❌ "2026년 6월 2일, 마이크로소프트가 AI를 발표했다."
- ✅ "10년 넘게 남의 엔진을 빌려 쓰던 회사가, 드디어 자기 걸 꺼냈어요."
- 가장 극적인 모순·아이러니를 앞부분에. 그다음 "그런데 설명서 한 줄이…" 같은 **떡밥**으로 끌고 들어간다.

## 3. 상단 필수 블록 (순서 고정)

1. **안내 콜아웃** — 출처 신뢰 고지. 예: "하나만 짚고 갈게요. 여기 점수·성능은 대부분 회사가 발표한 값이에요. 링크로 직접 확인을 추천해요."
   → 마크다운에서 `> **하나만 짚고 갈게요.** …` (인용 블록)
2. **세 줄 요약** — `# 세 줄 요약` + 불릿 3개. 사건의 핵심을 3줄로.

## 4. 소제목 — 번호 섹션 + 구어체

- 주요 섹션은 `# 1. …` `# 2. …`처럼 **번호로**. (디자인에서 고스트 챕터 번호 01·02…로 자동 렌더)
- 소제목만 훑어도 줄거리가 느껴지게. 도발적 질문/구어체 환영.
  - ✅ "근데 함정이 있어요", "그래서, 어떻게 봐야 할까요?"
- 소제목(더 작은 단위)은 `## …` (h3).

## 5. 스토리 흐름 — 떡밥 걸고 회수

- 앞에서 흘린 궁금증을 뒤에서 실제로 회수한다.
  - 예: 1번에서 "설명서에서 뭔가 발견했어요 (뒤에 나와요)" → 4번에서 회수.
  - 예: 3번에서 "이 '싸다'는 자랑이 나중에 문제와 겹쳐요 (6번에서)" → 6번에서 회수.
- 섹션 끝/시작에 연결 문장을 둬서 다음으로 넘어가게.

## 6. 비유 — 일상에서만, 섹션당 1개, 착지 필수

- ✅ 좋은 예(실제 사용): 큰 병원의 의사 100명 중 3~4명만 진료(MoE) / 담배갑 성분표 vs 광고 문구(성능 vs 마케팅) / 마트에서 산 물건 = 허락받음 vs 출처만 앎 / 모범생 노트 베끼기(증류).
- ❌ 학술 비유(죄수의 딜레마, 눈덩이 효과 등) 지양.
- 비유 뒤엔 반드시 **"= 원래 상황에선 이런 뜻"** 한 줄로 착지.

## 7. 문장·단어 — 짧고 쉽게

- 한 문장 25자 기본, 길면 쪼갠다.
- **전문 용어는 쉬운 말 먼저, 용어는 뒤에(괄호로 풀이).**
  - ✅ "덩치를 세는 단위를 **파라미터**라고 해요."
  - ✅ "필요한 부분만 깨워 쓰는 구조를 **MoE**(전문가 혼합)라고 불러요."
  - 실제로 푼 용어들: 파라미터 · MoE · 증류 · 벤치마크 · 토큰 · 구독제/종량제.

## 8. 재미 장치 — 최소 4개 심는다

1. 반전 전환문: "근데 잠깐. 여기 함정이 있어요.", "여기서 반전이 나와요."
2. 짧은 펀치라인(한 줄 문단): "토큰을 적게 쓴다 = 돈이 덜 든다는 뜻이에요."
3. 독자 참여: "기억나죠?", "이상하죠?"
4. 떡밥 회수(5번 참조).
   ※ 단, 재미가 정확성을 이기지 않게. 사실은 손대지 않는다.

## 9. 정직성 — 절대 지킴

- 소스에 없는 사실(수치·인용·URL)을 **지어내지 않는다.**
- 회사가 발표한 값은 **"발표값/주장"이라고 명시**하고, 링크로 직접 확인을 유도한다.
- **양쪽 말을 다 듣는다.** ("이게 성능이 가짜라는 뜻은 아니에요", "법을 어긴 것도 아니고요")
- 확인 못 한 각도는 "확인하지 못했어요"라고 솔직히.

## 10. 결론 — 이분법 거부

- "성공 아니면 실패" 식으로 몰지 않는다.
- "잘 만든 것"과 "광고가 컸던 것"은 **둘 다 사실일 수 있다** — 판단 재료만 주고 독자에게 맡긴다.
- 마지막에 **"앞으로 지켜볼 것" 3가지** 정도로 후속 관전 포인트를 준다.

## 11. 출처 — 문장마다 인라인 + 하단 목록

- 중요한 수치·주장에는 **문장 안에 마크다운 링크** `[텍스트](URL)`.
- 글 끝 `# 출처`에 분류별 목록(직접 자료 / 데이터 / 성능·시험 / 분석·리뷰 등).

## 문단 리듬 (줄바꿈) — 매우 중요

원칙: **관련 문장은 한 문단으로 묶고, 강조할 지점에서만 줄을 바꾼다.** (문장마다 다 쪼개지 말 것.)

- **한 문단으로 묶기**: 이어지는 설명·부연·비유 전개.
- **줄바꿈(새 문단)으로 띄우기**:
  - 펀치라인/반전("근데 잠깐…", "= 돈이 덜 든다는 뜻이에요")
  - 떡밥/후크("6번에서 나와요")
  - 용어 각주("(MoE, 전문가 혼합이라고 불러요)")
  - 리스트·인용·표 도입부, "한 줄로:" 요약

## 분량

- 심층 1편 기준 약 60~110문단(짧은 문단 위주), 읽기 8~12분.
- 재미 장치 4개 이상, 비유 섹션당 1개, 용어 풀이 필요할 때마다.

## 디자인 연동 규칙 (마크다운 관례 → 자동 변환)

`build-seo.mjs`가 마크다운을 아래 관례로 자동 렌더한다. **글 쓸 때 이 관례를 지키면 디자인이 알아서 입혀진다.**

| 쓰는 법 | 렌더 결과 |
|---|---|
| `# 1. 제목` (숫자 섹션) | 고스트 챕터 번호 **01** + 제목 *(layout:feature일 때)* |
| 표 헤더 마지막 칸에 "설명서/실제" 포함 | **주장 vs 실제 빨강 대조 표** *(feature)* |
| `**근데 잠깐…**` 볼드 문단 + 다음 문단 | **앰버 반전 콜아웃** *(feature)* |
| `= 설명…` 로 시작하는 문단 | 파란 콜아웃(설명 착지) |
| 상단 `> …` 인용 블록 | 파란 좌측 바 안내 박스 |
| `[텍스트](URL)` | 인라인 링크(볼드 중첩도 렌더됨) |
| `---` | `* * *` 구분선(주제 전환) |

- 원고 맨 위는 `# 제목` + `> 유형·상태 메타` + `---` 순. 이 블록은 발행 시 자동으로 **잘려서** 본문에 안 나온다(제목은 posts.json이 담당).
- **오렌지 = 브랜드(헤더·홈), 블루 = 본문 콘텐츠(콜아웃·링크·엣지).** 본문 색은 블루 유지.

## 발행 절차

1. 원고를 `drafts/<slug>/v1.md`에 저장.
2. `posts.json`의 `posts`에 항목 추가:
   `id, title, date, type, category(인사이트/리서치/튜토리얼), stage:"발행", layout:"feature", readMin, author:"AI 쉽게 알려주는 집", angle, versions:[…]`.
   - `angle` = 메타 description(155자 내 권장) + 홈 카드 standfirst.
   - `layout:"feature"` = A+B 하이브리드(고스트 번호·빨강 대조·앰버 반전).
3. **`node build-seo.mjs` 실행** — 정적 페이지·OG·sitemap·feed 생성. (안 돌리면 검색·공유에 안 잡힘)
4. 생성물 전체 커밋·푸시. (SEO 설계는 `system/seo.md`)

## 발행 전 체크리스트

- [ ] 전부 **해요체**인가?
- [ ] 도입이 사실 나열이 아니라 **장면/모순**으로 여는가?
- [ ] 상단에 **안내 콜아웃 + 세 줄 요약**이 있는가?
- [ ] 섹션이 **번호(`# 1.`)** 로 되어 있고, 소제목이 구어체인가?
- [ ] **떡밥을 걸고 실제로 회수**했는가?
- [ ] 비유마다 **"= 원래 뜻"** 착지가 있는가?
- [ ] 어려운 용어를 **쉬운 말 먼저 + 괄호 풀이**로 처리했는가?
- [ ] 발표값을 **"주장"으로 명시**하고 **양쪽 말**을 실었는가?
- [ ] 결론을 **한쪽으로 몰지 않고** 판단을 독자에게 맡겼는가?
- [ ] 중요한 주장마다 **인라인 출처 링크** + 하단 `# 출처` 목록이 있는가?
- [ ] **문단 리듬** — 강조엔 줄바꿈, 이어지는 설명은 묶었는가?
- [ ] `node build-seo.mjs` 돌리고 h1 1개·표·링크가 정상인가?
