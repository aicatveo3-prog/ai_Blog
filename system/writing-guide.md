# ✍️ 글쓰기 가이드 — 'AI 쉽게 알려주는 집'

> 이 블로그의 **정본 글쓰기 기준**. 모든 발행 글은 이 문서를 통과해야 한다.
> 확립 근거: `microsoft-mai` v1→v5에서 정리한 규칙 + `illinois-ai-law` v1→v4에서 추출한 압축·절제 규칙(12~14, 7·8 확장).
> **골드 스탠다드(실물 예시)**: `drafts/microsoft-mai/v1.md` — 애매하면 이 파일을 열어 **원리(후크·앵커·리듬)만** 가져온다. **문장을 베끼지 말 것.**
> (옛 `style-guide.md`는 이 문서로 대체됨.)

---

## 이 문서를 읽는 법 (규칙의 형식)

크래프트 규칙(1~11 + 문단 리듬)은 **네 블록**으로 쓴다:

- **[목표]** — 이 규칙이 지키려는 것(불변식). 왜 하는지.
- **[검증]** — 통과했는지 확인하는 테스트. 애매하면 이걸로 판정한다.
- **[경계]** — 넘지 말 것(❌). 실패 모드를 보여준다.
- **[형태]** — 어떻게 쓰는지는 **자유**. 규칙은 목표·경계만 못박고, 문장 형태는 매번 새로 짠다.

> **원칙: 규칙은 "무엇을·왜·어떻게 검증"만 자세히. "어떻게 쓰는지(형태)"는 규칙으로도 예시로도 못박지 않는다.**

- 한 줄짜리 ✅ "좋은 예"는 **최소화**한다 — 템플릿이 되어 창의성을 죽이기 때문.
- 실물 목소리·리듬은 **골드 스탠다드 전체 글**에서 감을 잡되, 문장을 베끼지 말고 '어떻게 됐나'의 **원리만** 가져온다.
- **예외**: 문법 형식이 곧 규칙인 것(해요체 종결, 용어 풀이 형식 등)은 예시를 남긴다 — 이건 창의적 선택이 아니라 지켜야 할 형식이라서.
- **아래쪽 기계적 섹션**(디자인 연동·발행 절차·체크리스트)은 일부러 못박는다 — 거긴 자유가 아니라 정확한 재현이 목적.

## 한 줄 원칙

> **"어려운 AI 뉴스를, 학생도 이해하게, 쉽고 재밌게. 단, 정확성은 절대 안 굽힌다."**

쉬운데(중학생도 이해) 안 유치하고, 재밌는데(계속 읽게 됨) 안 가볍다.
팩트는 정확하고, 판단은 독자에게 맡긴다.

## 독자 & 브랜드

- **독자**: AI에 관심은 있지만 전문가는 아닌 사람 — 학생·비전공자 눈높이.
- **브랜드 약속**: 복잡한 최신 AI 소식을 "쉽게 알려주는 집". 어려운 용어는 빼거나 풀고, 핵심만.
- **톤 한마디**: 똑똑한 친구가 옆에서 커피 마시며 설명해주는 느낌.

## 1. 문체 — 해요체

- **[목표]** 똑똑한 친구가 옆에서 설명하는 톤. 친근하지만 예의 있게.
- **[검증]** 모든 문장 종결이 해요체인가? 딱딱함도 반말도 없나?
- **[경계]**
  - ❌ '~합니다'체(딱딱), 반말
  - ❌ 관료체: "~에 관하여", "~라는 측면에서"
- **[형태]** 어휘·리듬은 자유. 단 **해요체 종결은 고정 형식**: "공개했어요 / 써요 / 걸렸어요". 긍정형 우선(안 되는 것도 되는 방향으로 돌려서).

## 2. 도입 — 후크 + 앵커

- **[목표]** 도입은 **두 가지를 동시에**. 하나라도 빠지면 실패다.
  - **후크** — 끌어당기는 긴장·모순·아이러니.
  - **앵커** — 누가·무엇을 했는지가 **즉시** 잡힘.
- **[검증]** 낯선 사람이 도입 **3문장만** 읽고 ①누가 ②무엇을 ③왜 흥미로운지가 다 잡히면 통과. 하나라도 안 잡히면 다시.
- **[경계]**
  - ❌ **마른 나열**: "○월 ○일, ○○사가 글을 올렸어요." → 긴장이 없다.
  - ❌ **과잉 각색**: "78겹의 저주가 실리콘 제국을 흔들었어요." → 무슨 뉴스인지 모른다.
- **[형태]** 자유다. 두 주장 충돌로 열든, 한 장면 클로즈업으로 열든, 인물로 열든 상관없다. 추상적으로 열면 **바로 다음 문장에서 정체를 밝힌다**(끝까지 숨기는 수수께끼 금지). 그다음 떡밥으로 본문에 진입.

## 3. 상단 필수 블록 — 세 줄 요약

- **[목표]** 본문 들어가기 전 **3줄 스캔**을 준다. 출처 신뢰는 인라인 링크 + 하단 출처란이 담당.
- **[형태]** `# 세 줄 요약` + 불릿 3개. 사건의 핵심을 3줄로.
- **[경계]** ❌ 안내 콜아웃(`> **하나만 짚고 갈게요.** …`) 삽입 — 본문 진입 전 벽이 된다. 쓰지 않는다.

## 4. 소제목 — 번호 섹션 + 구어체

- **[목표]** 소제목만 훑어도 **줄거리가 느껴지게**.
- **[검증]** 목차(소제목)만 읽어도 사건 흐름이 잡히나?
- **[경계]** ❌ 밋밋한 명사구 제목("성능 분석", "시장 반응")
- **[형태]** 주요 섹션은 `# 1. …` 번호(고스트 챕터 자동 렌더), 더 작은 단위는 `## …`(h3). 도발적 질문·구어체 환영 — 문구는 자유.

## 5. 스토리 흐름 — 떡밥 걸고 회수

- **[목표]** 앞에서 흘린 궁금증을 뒤에서 **실제로 회수** → 끝까지 읽게.
- **[검증]** 걸어둔 떡밥이 **전부 회수**됐나? (회수 안 될 떡밥은 애초에 안 건다.)
- **[경계]** ❌ 떡밥만 걸고 안 갚기(낚시) / ❌ 섹션이 툭툭 끊겨 연결이 없음
- **[형태]** 섹션 끝·시작에 연결 문장. 어디서 걸고 어디서 갚을지는 사건마다 자유.

## 6. 비유 — 일상에서만, 섹션당 1개, 착지 필수

- **[목표]** 어려운 개념을 **일상 감각**으로 옮긴다.
- **[검증]** 비유 뒤에 **"= 원래 상황에선 이런 뜻"** 착지가 있나? 한 섹션에 1개를 넘지 않나?
- **[경계]** ❌ 학술 비유(죄수의 딜레마, 눈덩이 효과 등) / ❌ 착지 없는 비유 / ❌ 한 섹션에 비유 남발
- **[형태]** 소재는 일상에서 자유롭게. *과거 사용례(재탕 말고 감만)*: 큰 병원 의사 100명 중 3~4명만 진료(MoE) · 담배갑 성분표 vs 광고 문구(성능 vs 마케팅) · 모범생 노트 베끼기(증류).

## 7. 문장·단어 — 짧고 쉽게

- **[목표]** 중학생도 한 번에 이해.
- **[검증]** 한 문장이 너무 길지 않나(길면 쪼갠다)? 전문 용어에 쉬운 풀이가 붙었나?
- **[경계]**
  - ❌ 용어를 설명 없이 던지기 / ❌ 한 문장에 여러 개념 욱여넣기
  - ❌ 관용구·사자성어로 뜻을 대신하기 ("사다리 걷어차기", "눈덩이 효과" 등) — 비유적 표현 대신 **실제로 무슨 일이 일어나는지를 직접 풀어쓴다**. 예: ~~"사다리 걷어차기"~~ → "큰 회사는 감당할 수 있지만, 작은 회사는 부담이 커요. 결과적으로 큰 회사만 유리해지는 거예요."
- **[형태]** **용어 풀이는 고정 형식** — 쉬운 말 먼저 + 괄호 용어: "필요한 부분만 깨워 쓰는 구조를 **MoE**(전문가 혼합)라고 불러요." (형식은 유지, 문장 내용은 자유.)

## 8. 재미 장치 — 최소 4개 심는다

- **[목표]** 계속 읽게 만드는 장치. 단 **재미가 정확성을 이기지 않게**.
- **[검증]** 재미 장치가 4개 이상인가? 사실을 왜곡한 재미는 없나?
- **[경계]**
  - ❌ 사실을 비틀어 만든 재미 / ❌ 억지 드립
  - ❌ **억지 드라마 단어**: "반전", "정작", "진짜 재밌는 건", "놀라운 건" — 팩트가 스스로 긴장을 만들게 놔둔다. 작성자가 "여기 놀라워!" 하고 밀면 독자는 오히려 식는다.
- **[형태]** 종류를 자유롭게 섞는다 — 반전 전환문 · 짧은 펀치라인(한 줄 문단) · 독자 참여("기억나죠?") · 떡밥 회수. 문구는 매번 새로.

## 9. 정직성 — 절대 지킴 (예외 없음)

- **[목표]** 신뢰가 브랜드의 전부. **사실은 절대 손대지 않는다.**
- **[검증]** 모든 수치·인용·URL이 소스에 실재하나? 발표값을 "주장"으로 명시했나? 양쪽 말을 실었나?
- **[경계 — 절대 금지]**
  - ❌ 소스에 없는 사실·수치·URL을 지어내기
  - ❌ 회사 발표값을 확정 사실처럼 쓰기
  - ❌ 한쪽 말만 싣기
- **[형태]** 표현은 자유지만 이 경계는 예외가 없다. 확인 못 한 각도는 **"확인하지 못했어요"**라고 솔직히.

## 10. 결론 — 이분법 거부

- **[목표]** 판단은 독자에게. **재료만** 준다.
- **[검증]** "성공/실패"로 몰지 않았나? 마지막에 **"앞으로 지켜볼 것" 3가지**가 있나?
- **[경계]** ❌ 한쪽으로 결론 강요 / ❌ "결국 ~이다" 식 단정
- **[형태]** "잘 만든 것"과 "광고가 컸던 것"이 **둘 다 사실일 수 있음**을 보여준다. 마무리 형태는 자유.

## 11. 출처 — 인라인 + 하단 목록

- **[목표]** 모든 주장을 **원문으로 되짚을 수 있게**.
- **[검증]** 중요한 수치·주장마다 인라인 링크가 있나? 글 끝 `# 출처` 목록이 있나?
- **[경계]** ❌ 링크 없는 수치·주장 / ❌ 지어낸 URL(9번과 연결)
- **[형태]** 인라인은 `[텍스트](URL)`. 하단 `# 출처`는 분류별(직접 자료 / 데이터 / 성능·시험 / 분석·리뷰).

## 12. 반복 금지 — 같은 말은 3번까지

- **[목표]** 같은 포인트를 표현만 바꿔 반복하면 글이 늘어지고, 독자가 "또 이 얘기?"하게 된다. 한 번 잘 말하면 된다.
- **[검증]** 같은 팩트·주장이 글 전체에서 3번 이상 나오지 않나? (세 줄 요약 1번 + 본문 설명 1번 + 결론 회수 1번 = 최대 3번)
- **[경계]** ❌ 같은 포인트를 표현만 바꿔 4번 이상 반복 / ❌ "아까 말했듯이"로 시작하는 재탕 문단
- **[형태]** 반복이 보이면 가장 강한 한 문장만 살리고 나머지를 지운다.

## 13. 정보 압축 — "빼도 핵심이 사나?" 테스트

- **[목표]** 모든 문단이 글의 핵심 주장을 뒷받침하는지 확인한다. 안 그러면 삭제.
- **[검증]** 각 문단을 빼고 읽어본다. **빼도 글의 핵심 주장이 살아있으면 그 문단은 불필요하다.**
- **[경계]** ❌ "있으니까 넣자" 식 정보 나열 / ❌ 맥락 설명이 본론보다 긴 글
- **[형태]** 팩트 나열은 표로 압축. 부가 정보는 한 줄로 줄이거나 삭제.

## 14. 비중 배분 — 팩트는 짧게, "왜?"에 지면을 쓴다

- **[목표]** 독자가 궁금한 건 "무슨 일이 있었나"보다 "그래서 왜 중요한데?"다. 팩트 전달은 압축하고, 분석·맥락·의미에 분량을 준다.
- **[검증]** 팩트 전달 섹션이 분석 섹션보다 길지 않나? 팩트는 표·불릿으로 압축했나?
- **[경계]** ❌ "누가 뭘 했다"만 길게 나열하고 "왜 중요한지"는 한 줄 / ❌ 분석 없이 팩트만 전달하는 기사체
- **[형태]** 팩트는 표·불릿으로 압축. 남은 지면은 "왜?", "나한테 무슨 상관?", "앞으로 어떻게?"에 쓴다.

## 문단 리듬 (줄바꿈) — 매우 중요

- **[목표]** 관련 문장은 한 문단으로 **묶고**, 강조할 지점에서만 줄을 바꾼다. (문장마다 다 쪼개지 말 것.)
- **[검증]** 이어지는 설명이 한 문단으로 묶였나? 줄바꿈이 강조·전환에만 쓰였나?
- **[경계]** ❌ 모든 문장 줄바꿈(리듬 사망) / ❌ 한 문단에 여러 주제 뭉치기
- **[형태]** 새 문단으로 띄우는 곳: 펀치라인·반전("근데 잠깐…") · 떡밥/후크("6번에서 나와요") · 용어 각주 · 리스트·인용·표 도입부 · "한 줄로:" 요약.

## 분량

- 심층 1편 기준 약 60~110문단(짧은 문단 위주), 읽기 8~12분.
- 재미 장치 4개 이상, 비유 섹션당 1개, 용어 풀이 필요할 때마다.

## 디자인 연동 규칙 (마크다운 관례 → 자동 변환)

`build-seo.mjs`가 마크다운을 아래 관례로 자동 렌더한다. **글 쓸 때 이 관례를 지키면 디자인이 알아서 입혀진다.**

| 쓰는 법 | 렌더 결과 |
|---|---|
| `# 1. 제목` (숫자 섹션) | 고스트 챕터 번호 **01** + 제목 *(layout:feature일 때)* |
| 표 헤더 마지막 칸에 "설명서/실제" 포함 | **주장 vs 실제 빨강 대조 표** *(feature)* |
| `**근데 잠깐…**` 볼드 문단 + 다음 문단 | **앰버 반전 콜아웃** *(feature)* |
| `= 설명…` 로 시작하는 문단 | 파란 콜아웃(설명 착지) |
| 상단 `> …` 인용 블록 | 파란 좌측 바 안내 박스 |
| `[텍스트](URL)` | 인라인 링크(볼드 중첩도 렌더됨) |
| `---` | `* * *` 구분선(주제 전환) |

- 원고 맨 위는 `# 제목` 다음 **바로 `# 세 줄 요약`** 으로 간다. 제목 줄은 발행 시 자동으로 잘린다(제목은 posts.json이 담당).
  - `# 제목` 뒤에 `> 유형·상태 메타` + `---` 블록을 넣는 건 **선택**이다. 넣으면 첫 `---`까지 자동으로 잘려 본문에 안 나온다(옛 글 호환). **굳이 안 써도 된다.**
- **글 페이지에는 standfirst(제목 아래 회색 요약문)를 렌더하지 않는다.** 세 줄 요약과 겹쳐 군더더기가 되기 때문. `angle`은 홈 카드 설명·SEO 메타로만 쓰인다.
- **오렌지 = 브랜드(헤더·홈), 블루 = 본문 콘텐츠(콜아웃·링크·엣지).** 본문 색은 블루 유지.

## 발행 절차

1. 원고를 `drafts/<slug>/v1.md`에 저장.
2. `posts.json`의 `posts`에 항목 추가:
   `id, title, date, type, category(인사이트/리서치/튜토리얼), stage:"발행", layout:"feature", readMin, author:"AI 쉽게 알려주는 집", angle, versions:[…]`.
   - `angle` = SEO 메타 description(155자 내 권장) + 홈 카드 설명(`.dek`). **글 페이지 본문엔 안 나온다.**
   - `layout:"feature"` = A+B 하이브리드(고스트 번호·빨강 대조·앰버 반전).
3. **`node build-seo.mjs` 실행** — 정적 페이지·OG·sitemap·feed 생성. (안 돌리면 검색·공유에 안 잡힘)
4. 생성물 전체 커밋·푸시. (SEO 설계는 `system/seo.md`)

## 발행 전 체크리스트

- [ ] 전부 **해요체**인가?
- [ ] 도입이 **후크(긴장)+앵커(누가·무엇을 3초 내)** 를 둘 다 갖췄는가? (마른 나열도, 과잉 각색도 아님)
- [ ] 상단에 **세 줄 요약**이 있는가? (안내 콜아웃은 쓰지 않는다)
- [ ] 섹션이 **번호(`# 1.`)** 로 되어 있고, 소제목이 구어체인가?
- [ ] **떡밥을 걸고 실제로 회수**했는가?
- [ ] 비유마다 **"= 원래 뜻"** 착지가 있는가?
- [ ] 어려운 용어를 **쉬운 말 먼저 + 괄호 풀이**로 처리했는가?
- [ ] 발표값을 **"주장"으로 명시**하고 **양쪽 말**을 실었는가?
- [ ] 결론을 **한쪽으로 몰지 않고** 판단을 독자에게 맡겼는가?
- [ ] 중요한 주장마다 **인라인 출처 링크** + 하단 `# 출처` 목록이 있는가?
- [ ] **억지 드라마 단어**(반전·정작·진짜 재밌는 건 등)를 안 썼는가?
- [ ] 같은 포인트가 **3번 이상 반복**되지 않았는가?
- [ ] 각 문단을 빼봤을 때 **핵심이 사는지** 확인했는가? (안 사는 문단만 남긴다)
- [ ] 관용구·사자성어 대신 **뜻을 직접 풀어** 썼는가?
- [ ] **팩트는 표·불릿으로 압축**하고 **분석·맥락에 지면**을 줬는가?
- [ ] **문단 리듬** — 강조엔 줄바꿈, 이어지는 설명은 묶었는가?
- [ ] `node build-seo.mjs` 돌리고 h1 1개·표·링크가 정상인가?
