# 직접 테스트 프로토콜 — 이 블로그의 핵심 자산

> AI가 생성할 수 없고, E-E-A-T "경험" 신호가 되며, 독자가 원문 대신 내 글을 읽을 유일한 이유.
> **표준 시나리오를 고정**한다 — 새 도구가 나올 때마다 뭘 테스트할지 고민하지 말고, 아래 3개를 모든 도구에 동일 적용한다. 그러면 도구 간 정량 비교가 가능해지고, 나만의 비교 데이터셋이 쌓인다.

---

## 표준 시나리오 3종

| 시나리오 | 내용 | 측정 항목 |
|---|---|---|
| **S1 정보 파이프라인** | RSS 수집 → AI 요약 → 슬랙 알림 | 구축 시간, 월 비용, 실패율 |
| **S2 문서 자동화** | 이메일/폼 입력 → 분류 → 시트 기록 → 자동 회신 | 구축 시간, 분류 정확도 |
| **S3 에이전트 태스크** | "특정 주제 리서치 후 요약 보고" 자율 수행 | 성공률, 토큰 비용, 소요 시간 |

---

## 테스트 로그 (필수 필드) — 도구마다 복사해서 채운다

```markdown
# 테스트 로그: [도구명] / [시나리오 S?]
- 테스트 날짜:
- 도구 버전:
- 설정 소요 시간 (실측):        분
- 막힌 지점과 해결 과정:
- 발생 비용:                    원 (또는 토큰/크레딧)
- 실행 속도:                    초
- 10회 실행 시 실패 횟수:       /10
- 결과물 스크린샷 경로:         (반드시 본인 캡처)
- 솔직한 한 줄 평:
```

> 이 로그가 그대로 조사 노트 D섹션 → P1 팩트 목록으로 흘러간다.
