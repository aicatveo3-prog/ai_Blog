# 프롬프트 L — 기존 수집물 출처 링크 백필

> 용도: 이미 만들어진 `collect/` 파일(정리본·자세히·**반응**)에 **인라인 출처 링크**와
> **하단 raw URL 목록**을 채워 넣는다. 기준은 프롬프트 J·H의 "철칙 0 — 모든 정보는 클릭 가능".
> 링크가 빠진 채 쌓인 과거 수집물을 사후 보정할 때 쓴다.
>
> 대상 확인: `ls collect/*-summary.md collect/*.md collect/reactions/*.md`
> 관련: `prompts/J-collect-explainers.md`, `prompts/H-reactions-multiangle.md`, `system/daily-collection.md`.

---

## 프롬프트 본문 (그대로 전달)

```text
작업: collect/ 폴더의 이미 만들어진 수집물에 출처 링크를 채운다.
대상 = 정리본(collect/*-summary.md) · 자세히(collect/*.md) · 반응(collect/reactions/*.md).

기준(prompts/J·H 철칙 0):
- 본문의 모든 사실·수치·인용·매체명에 그 자리 인라인 링크 [텍스트](URL).
- 반응 파일은 각 항목이 - [출처명](URL): 요약 형식으로 시작하도록 링크를 붙인다.
- 하단 '# 출처'(반응은 '## 출처') 목록에 제목 하이퍼링크 + 실제 전체 주소를 둘 다 남긴다:
    # 출처
    - [매체 · 한 줄 제목](URL)
      [URL 전체 주소 그대로](URL)

규칙(정직성 — 가장 중요):
1. 링크는 각 파일 하단의 기존 출처 목록 + inbox.json의 해당 항목 source·verifyNote에 있는
   '실제 URL'만 우선 사용한다.
2. 하단 목록에 없는 주장인데 링크가 필요하면, WebSearch로 1차·신뢰 출처를 찾아
   '확인된 경우에만' 링크한다. 못 찾으면 링크를 만들지 말고 문장을 그대로 둔다.
   → URL을 절대 지어내지 않는다. 매체와 내용이 안 맞는 엉뚱한 출처에 연결하지 않는다.
3. 사실·문장·수치·표현을 바꾸지 않는다. 오직 링크만 추가한다.
4. 이미 인라인 링크가 충분한 파일(예: 최근 정리본/자세히, illinois 반응 등)은 하단 raw URL
   목록만 보강하고 본문은 그대로 둔다.

절차:
- 파일 하나씩: 읽기 → 인라인 링크 + 하단 raw URL 목록 추가 → 저장.
- 소식이 많으면 소식당 서브에이전트 1개를 병렬로(각자 자기 slug의 3개 파일만 손대 충돌 방지).
- inbox.json은 중앙에서 한 번에 갱신(공유 파일 경쟁 방지).
- 끝나면 claude/github-upload-setup-vimtlp 브랜치에 커밋·푸시.
- 마지막에 '파일별 추가한 인라인 링크 수 + raw URL 목록 유무'를 표로 보고한다.
```
