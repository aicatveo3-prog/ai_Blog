# AI 자동화 블로그 — 고품질 콘텐츠 생산 시스템 설계서 (v1)

> 목적: "AI 자동화 관련 최신 소식을 찾고 → 분석하고 → 퀄리티 있는 글을 쓰는" 전 과정을 하나의 운영 시스템으로 설계한다.
> 사용법: 이 문서는 한 번 읽고 끝나는 글이 아니라, 블로그의 **운영 매뉴얼 v1**이다. 운영하면서 버전을 올려간다.
>
> 이 파일은 **진실의 원천(source of truth)**이다. 각 장의 규칙은 `system/`, `prompts/`, `automation/` 폴더에 실제 사용 가능한 형태로 분리되어 있으며, 이 문서는 그 전체 그림을 설명한다.

---

## 1. 문제 정의 — 퀄리티는 어디서 결정되는가

### 1.1 전제: 글쓰기 단계는 병목이 아니다
누구나 AI로 "그럴듯한 글"을 무한정 뽑을 수 있어 그 시장 가치는 0에 수렴했다. 경쟁자와 나의 차이는 "문장을 얼마나 잘 뽑느냐"에서 생기지 않는다. 퀄리티의 실제 병목은 글쓰기의 앞과 뒤, 네 지점에 있다.

| 병목 | 질문 | 못하면 생기는 일 |
|---|---|---|
| ① 소스의 질 | 남들이 안 보는 1차 소스를 보는가 | 2차 기사 재탕, 항상 반 박자 늦음 |
| ② 선별 안목 | 무엇을 다루고 무엇을 버리는가 | 정체성 없는 잡탕 블로그 |
| ③ 관점 | 같은 뉴스에서 다른 해석을 내는가 | "요약 봇"과 구분 불가 |
| ④ 직접 경험 | 그 도구를 실제로 돌려봤는가 | AI가 대체 가능한 글만 남음 |

목표: **사람의 시간을 이 네 곳에 집중시키고, 나머지는 최대한 기계에 넘긴다.**

### 1.2 설계 철학 3원칙
1. **70/70 규칙** — 기계가 시간의 70%를 절약하되, 글 가치의 70%는 사람이 넣는다.
2. **자동화는 병목의 앞에 배치한다** — 수집·정리·초안은 자동화, 판단·경험·승인은 절대 자동화하지 않는다.
3. **프롬프트는 코드다** — 스타일 가이드·프롬프트·체크리스트를 전부 문서화하고 버전 관리한다.

## 2. 전체 아키텍처

### 2.1 7단계 파이프라인
```
[1 수집] → [2 선별] → [3 심층조사] → [4 분석·관점] → [5 초안작성] → [6 검수] → [7 발행·피드백]
  자동        반자동      사람+AI보조     사람+AI보조      반자동         사람        반자동
```

| 단계 | 산출물 | 자동화 적합도 | 사람의 역할 | 부실하면 |
|---|---|---|---|---|
| 1 수집 | 인박스 후보 항목 | ★★★★★ | 소스 리스트 관리 | 글감이 늦고 얕음 |
| 2 선별 | 이번 주 2~4건 | ★★★☆☆ | 최종 선택(편집장) | 정체성 소멸 |
| 3 조사 | 조사 노트 + 테스트 로그 | ★★☆☆☆ | 원문 읽기, 직접 테스트 | 재탕, 오류 |
| 4 분석 | 관점 한 문장 + 논거 | ★★☆☆☆ | 해석과 판단 | 요약 봇화 |
| 5 작성 | 초안 | ★★★★☆ | 아웃라인 승인, 최종 편집 | 시간 낭비 or AI 냄새 |
| 6 검수 | 발행 승인 원고 | ☆☆☆☆☆ | 팩트체크, 게이트 판정 | 환각 발행 → 신뢰 파산 |
| 7 발행·피드백 | 발행물 + 지표 | ★★★★☆ | 월간 역분석 | 시스템이 안 좋아짐 |

### 2.2 항목의 상태 머신
```
인박스 → 검토중 → 선정 → 조사중 → 작성중 → 검수중 → 발행
                ↘ 보류(에버그린 후보)    ↘ 폐기(사유 기록)
```
폐기 시 사유를 한 줄 남긴다. 3개월치 폐기 사유가 곧 나의 편집 기준 데이터가 된다.

## 3. 1단계 — 수집 (Ingestion)
→ 실제 소스 리스트: [`system/sources.md`](../system/sources.md)
→ 수집 자동화 설정: [`automation/n8n-workflows.md`](../automation/n8n-workflows.md), [`automation/notion-inbox-schema.md`](../automation/notion-inbox-schema.md)

### 3.1 1차 소스 원칙
**발표 주체의 원문(1차) → 커뮤니티 반응(2차) → 큐레이션(보조)** 순서. 큐레이션 뉴스레터는 "놓친 게 없는지 확인하는 안전망"으로만 쓰고, 글의 소스로 삼지 않는다.

### 3.2 소스 리스트 → `system/sources.md`

### 3.3 수집 자동화 (n8n): 세 워크플로로 분리
- **A — RSS 폴링(2시간)**: 트리거 → RSS 읽기 → Merge → URL 정규화·중복제거 → 키워드 화이트/블랙리스트 → 경량 AI 요약·태깅·점수 → Notion 인박스 → 고점수 알림
- **B — HN·Reddit(6시간)**: HN Algolia API(points 필터) + 서브레딧 RSS → 이후 A와 동일
- **C — GitHub 릴리즈(1일 1회)**: releases.atom에서 메이저·마이너만
운영 팁: 각 워크플로에 에러 알림 노드. 모든 항목에 소스명 태그.

### 3.4 인박스 스키마 → `automation/notion-inbox-schema.md`

### 3.5 중복과 클러스터링
큰 발표는 소스 5~10곳에서 동시 유입. AI 노드에 "기존 항목과 같은 사건인가?"를 물어 Cluster로 묶고, 검토는 클러스터당 1회.

## 4. 2단계 — 선별 (Triage)
→ 채점 루브릭 + 킬 기준: [`system/scoring-rubric.md`](../system/scoring-rubric.md)

### 4.2 스코어링 루브릭 v1 (요약)
독자 영향도 30% / 차별화 여지 30% / 신선도 15% / 역량 적합 15% / 축적성 10%. AI 총점 상위 20%만 사람이 검토. **점수가 낮아도 감이 오면 선정하고 사유를 기록**한다.

### 4.4 사람의 결정 프로세스
주 1회 30분 "편집회의". 고점수 항목 훑기 → 슬롯 배정 → 각 건 "예상 관점 한 줄" 기록. 관점 한 줄이 안 떠오르면 선정하지 않는다.

## 5. 3단계 — 심층 조사 (Research)
→ 조사 노트 템플릿: [`system/research-note.md`](../system/research-note.md)
→ 직접 테스트 프로토콜: [`system/test-protocol.md`](../system/test-protocol.md)

### 5.1 원문 우선
① 공식 발표문·기술문서·모델카드 → ② 논문이면 한계(Limitations) 필독 → ③ HN·레딧 반응 → ④ 과거 맥락 → ⑤ 경쟁 도구 상태. 특히 ③의 실사용자 불만·엣지케이스가 차별화 지점의 금광.

### 5.2 직접 테스트 = 이 블로그의 핵심 해자
AI가 생성 못 하고, E-E-A-T "경험" 신호가 되며, 독자가 원문 대신 내 글을 읽을 유일한 이유. 표준 시나리오 3종을 고정해 모든 도구에 동일 적용.

## 6. 4단계 — 분석과 관점 (Analysis)
→ 관점 발산 프롬프트: [`prompts/B-perspective.md`](../prompts/B-perspective.md)

### 6.1 관점 한 줄 테스트
"X가 Y를 발표했다"는 관점이 아니다. "X의 Y는 표면적으론 기능 추가지만 실제론 Z 시장 포석이고, ~하는 사람은 지금 ~를 준비해야 한다" — 이런 문장이 나와야 관점이다.

### 6.2 5가지 분석 프레임워크
1. So-What 3단 체인 2. 이해관계자 매트릭스 3. 타임라인 포지셔닝 4. 반대 가설 5. 로컬 번역(한국 함의). 매 글마다 2~3개 적용.

### 6.3 AI는 발산용, 사람은 수렴용
"해석 각도 10개 생성 → 사람이 1~2개 선택 → 반박·보강 질문 → 사람이 최종 논지 확정." **선택과 확정은 항상 사람.**

## 7. 5단계 — 초안 작성 (Drafting)
→ 스타일 가이드: [`system/style-guide.md`](../system/style-guide.md)
→ 글 유형 템플릿: [`system/post-templates.md`](../system/post-templates.md)
→ 프롬프트 체인: [`prompts/`](../prompts/)

### 7.2 5단 프롬프트 체인
```
[P1 팩트추출] → [P2 아웃라인×2안] → ★사람 승인★ → [P3 섹션별 작성] → [P4 에디터 비판] → [P5 사람 편집]
```
- P1: 조사 노트 → 팩트 목록(출처·확실도). 이후 모든 문장은 이 목록 밖 사실 금지.
- P2: 아웃라인 2안 생성 → 사람이 선택·수정·승인. **가장 중요한 게이트.**
- P3: 스타일 가이드 + 기존 글 2편 + 승인 아웃라인. 섹션 단위 생성.
- P4: **새 대화**에서 "까다로운 시니어 에디터"로 공격. 산출물은 "수정 지시 목록".
- P5: 사람 편집. **전체 시간의 30~40% 배정.** 여기가 가치의 70%.

---

## 8. 6단계 — 검수 (Verification)
→ 체크리스트: [`system/checklists.md`](../system/checklists.md)

### 8.1 환각 리스크 지도
AI가 특히 지어내는 것: **벤치마크 수치, 출시일, 가격, 버전 번호, 인용문, 논문 저자명, "이 기능 있다/없다".** 초안의 모든 수치가 P1 팩트 목록에 있는지 역추적.

### 8.4 발행 게이트 — 마지막 3질문
① 독자가 원문 대신 이 글을 읽을 이유가 있는가? ② 나만 쓸 수 있는 문장은 정확히 어디인가? ③ 6개월 뒤 읽어도 부끄럽지 않은가? 하나라도 "아니오"면 보류. **보류는 실패가 아니라 시스템이 작동한다는 증거.**

## 9. 7단계 — 발행과 피드백 루프

### 9.1 플랫폼
장기전은 자체 블로그(Ghost/WordPress/Astro). 검증 단계는 티스토리·네이버. **뉴스레터는 초기부터 병행** — 구독자 목록만이 플랫폼·알고리즘에 종속되지 않는 자산.

### 9.2 퀄리티 지표 — 조회수의 함정
조회수는 낚시로도 오른다. 대신: 체류시간·완독률, 재방문율, 구독 전환율, 유입 검색어 질, 인용·백링크. **30일 룰**: 모든 글은 발행 30일 후 지표 기록.

### 9.3 월간 역분석
월 1회 1시간. 상위 3편·하위 3편을 "유형·소스·관점·제목"으로 비교 → 루브릭 가중치·프롬프트·킬 기준에 반영.

### 9.4 시스템 버전 관리
스타일 가이드·프롬프트·루브릭·체크리스트를 **이 Git 저장소**로 관리하고, 바꿀 때마다 "왜 바꿨는지" 한 줄 로그. 이 변경 이력 자체가 최고의 콘텐츠가 된다.

## 10. 자동화 수준 — 가장 중요한 의사결정

**반자동이 정답.** 완전 자동은 ① 품질 상한이 "AI 평균"에 고정, ② 구글의 대량생산 콘텐츠(scaled content abuse) 제재 대상, ③ 환각 수치 한 번 발행 = 신뢰 파산.

경계선 한 문장: **"수집·정리·초안·형식은 기계, 사실 판단·선별·관점·경험·최종 승인은 사람."**

메타 전략: **파이프라인 자체가 콘텐츠다.** "이 블로그는 n8n+Claude로 이렇게 만듭니다"가 곧 튜토리얼·포트폴리오·신뢰. 분기마다 개선기를 시리즈로.

## 11. 도구 스택과 비용
- 수집: n8n(셀프호스트) / 대안 Make·Zapier
- 인박스: Notion / 대안 Airtable
- 스코어링·요약: 경량 LLM (저비용, 대량)
- 초안·분석: 상위 LLM (Claude 프로젝트에 스타일 가이드 상주)
- 발행: Ghost/WordPress/Astro+GitHub Pages
- 뉴스레터: Stibee(국내)/Substack
- 지표: GA4 + Search Console + Clarity (전부 무료)

예산: 최소 0~2만원 / 표준(권장) 5~10만원 / 확장 15만원~. 모델 단가는 수시 변동 → 설계 시점에 공식 가격 페이지 확인, API 콘솔에 월 상한.

시작은 **n8n + Notion + LLM 1~2개 + 블로그** 네 조각으로 제한.

## 13. SEO와 E-E-A-T
- **경험 신호 심기**: 직접 캡처 스크린샷, 실측 수치("23분 걸렸다"), 실패담·우회법, 저자 소개.
- **토픽 클러스터**: 필러 페이지 + 개별 글 상호 내부링크.
- **위생 관리**: 얇은 글은 통합·삭제(리다이렉트).
- **AI 답변엔진 대응**: 나만의 데이터(직접 테스트 실측치, 비교표)를 심어 인용되는 쪽이 된다.

## 14. 실패 패턴 카탈로그
| # | 패턴 | 방지 장치 |
|---|---|---|
| 1 | 패러프레이즈 블로그 | 조사 노트 필수화, 게이트 질문 ① |
| 2 | AI 문체 방치 | 금지어 리스트, AI 냄새 체크 |
| 3 | 환각 수치 발행 | P1 팩트 역추적, 체크리스트 |
| 4 | 커버리지 함정 | 킬 기준, 주간 슬롯 상한 |
| 5 | 자동화 우선 함정 | 2주차 "수동 3편" 필수 |
| 6 | 지표 없는 운영 | 30일 룰, 월간 역분석 |
| 7 | 번아웃 설계 | 주 8~12시간 캘린더 |

**패턴 5가 가장 뼈아프다: 좋은 글을 먼저 손으로 만들 수 있어야 시스템화가 된다. 순서를 뒤집으면 평범한 글 대량생산 기계가 완성된다.**

## 15. 실행 로드맵
- **0~1주차 기반**: 포지셔닝 확정 → 소스 리스트 v1 → n8n 워크플로 A + Notion 인박스. 완료 기준: "아침에 열면 후보가 자동으로 쌓여 있다."
- **2주차 수동 3편**: 스타일 가이드·템플릿 작성 후 **거의 수동으로** 3편(브리핑2+심층1) 발행, 단계별 소요 시간 실측.
- **3~4주차 병목만 자동화**: 실측에서 가장 오래 걸린 단계에만 자동화 추가. 표준 테스트 3종 정의, 첫 직접 테스트 글.
- **2개월차 루프 가동**: 뉴스레터 개설, 첫 월간 역분석, 루브릭·프롬프트 v2.
- **3개월차 자산화**: 에버그린 필러 페이지, "이 블로그 파이프라인" 공개 글, 수익화 실험.
