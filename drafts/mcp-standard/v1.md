# MCP, 1년 만에 '표준'이 되다 — 도구의 USB-C 순간

> **유형** · B 심층(짧게)  **상태** · 검수중(P5 사람 편집 대기)
> **관점** · 작년까진 프레임워크마다 도구를 새로 붙였다. 이제 MCP 하나로 어디든 — 지금 MCP 지원 도구를 고르면 나중에 안 갈아엎는다.

**한 줄 요약** — Model Context Protocol(MCP)이 등장 1년 남짓 만에 **사실상 산업 표준**이 됐다. 프레임워크마다 도구를 새로 연결하던 시대가 끝나간다. "한 번 만들어 어디서나 쓴다."

---

## 무슨 일이 있었나

MCP는 이제 **거의 모든 major 에이전트 프레임워크가 네이티브로 지원**한다. [F1]

- **Microsoft Agent Framework** — 코어에 네이티브 MCP, Python·.NET **1.0을 4월 3일 동시 출시**. [F2]
- **LangChain** — 공식 어댑터(`langchain-mcp-adapters`)가 MCP 도구를 LangChain/LangGraph 도구로 변환. [F3]
- 새 기능(streamable HTTP, OAuth, structured outputs)은 **Anthropic MCP SDK에 먼저** 들어가고 나머지로 전파된다. [F4]

핵심은 한 문장이다 — **"Build once, use everywhere."** [F5]

## 왜 중요한가 — 도구의 USB-C 순간

예전엔 새 도구를 붙이려면 프레임워크마다 코드를 다시 짰다. 이제는 **MCP 서버 하나**를 만들면 프로토콜을 말하는 모든 곳에서 그대로 쓴다. USB-C처럼, 한 규격이 생태계를 통일하는 순간이다.

**그래서 나는** → 지금 자동화·에이전트를 설계한다면, **MCP를 지원하는 도구를 고르는 게 미래 비용을 아끼는 선택**이다. 프레임워크를 갈아타도 도구는 그대로 간다.

## ⚠️ 반대 가설도 짚고 넘어가자

"표준"이라지만 각 벤더가 제멋대로 확장하면 **다시 파편화**될 수 있다. [G] "MCP 지원"이라는 라벨만 보지 말고, 실제로 표준 스펙을 따르는지 확인하는 습관이 필요하다.

> 💬 **[경험 삽입]** MCP 도구를 두 개 이상 프레임워크에서 붙여본 경험이 있다면, 정말 그대로 옮겨갔는지 한 줄.
